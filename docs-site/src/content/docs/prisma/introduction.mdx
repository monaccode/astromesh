**Astromesh Prisma** <Badge text="in development" variant="caution" /> takes an agent you wrote for
Astromesh and turns it into **the target cloud's own native agent**, running on **that cloud's base
resources**. The YAML the runtime loads (`kind: Agent`, `kind: RAGPipeline`) stays the source of
truth, and a reconcile loop drives the cloud toward it, Kubernetes-operator style. GCP first.

Its distinguishing idea is a negative one. **Coverage gaps are explicit and never silently
dropped.** Whatever the native agent cannot do the way Astromesh does is reported, section by
section, and the coverage matrix is *generated from the mapping registry* instead of written by
hand. A test also walks the core's own agent schema and fails when the core adds a key Prisma has
not decided on.

## From your agent to GCP's agent

On GCP the native agent is an **ADK agent config** (`agent_class: LlmAgent`) that Agent Engine
deploys declaratively, through `spec.sourceCodeSpec.agentConfigSource.adkConfig`. Prisma does not
generate agent code. It writes that config and wires it to the resources the agent runs on:

| In your YAML | On GCP | How the native agent reaches it |
|---|---|---|
| `prompts.system`, `model`, sampling settings | the ADK config itself | `instruction`, `model`, `generate_content_config` |
| `memory.conversational` | Agent Engine **Sessions** | built into the engine |
| `memory.semantic` | the engine's **Memory Bank** | `preload_memory` reads it; a callback writes every turn to it |
| `knowledge.pipeline` | the **RAG Engine corpus** that pipeline's own manifest provisions | a retrieval tool bound to the corpus |
| `pii_detection` guardrail | a **Model Armor** template | `model_armor_config`, on the side the rule is declared |
| `type: client` tools | — | a long-running tool: the model asks, your app answers |
| `builtin` `web_search` | Google Search grounding | ADK's `GoogleSearchTool` |
| `orchestration.pattern: pipeline` | — | a `SequentialAgent`, one sub-agent per stage |

A reference to a resource whose full name only exists once it is created is written as a
**binding**, `prisma://{kind}/{manifest}/{resource_type}/{name}`, and the gateway resolves it at
deploy time. The GCP surface was read from the `aiplatform` v1 discovery document and the
`google-adk` 2.10.0 source, not from memory. The test suite then loads each generated config into
ADK, runs it with a recording model in place of Gemini, and checks the request ADK would send.

`POST /v1/translate` shows what an agent becomes without storing or deploying anything:

      "spec": {"agent_framework": "google-adk", "source_code_spec": {"agent_config_source": {
        "adk_config": {"json_config": {
          "agent_class": "LlmAgent", "name": "support_agent", "model": "gemini-2.5-flash",
          "instruction": "You help customers with their orders.",
          "tools": [{"name": "prisma_tools.client_tool", "args": {"name": "confirm_refund", "...": "..."}},

### What does not translate, and why

Among others:
- **Model routing and fallback.** A native agent has one model.
- **Episodic memory.**
- **`integration`, `api` and `mcp` tools.** A `writes: true` tool *proposes* in Astromesh, and an
  ADK toolset would execute it.
- **`parallel_fan_out`, `supervisor`, `swarm` and `glyph`.**
- **`content_filter`** (regex replacement) and **`topic_filter`**, which needs the agent
  registered in Agent Registry first.

Each shows up as a gap with that reason, not as silence.

## Prisma or Orbit?

Both put an Astromesh workload on a cloud. They disagree about who runs it.

| | [Orbit](/astromesh/orbit/introduction/) | Prisma |
|---|---|---|
| **What runs your agent** | The Astromesh runtime, on infrastructure you own | The cloud's own managed AI service |
| **What it produces** | Terraform you can eject to and keep | Native cloud resources, reconciled continuously |
| **You get** | The whole runtime: every pattern, every tool type | Whatever that cloud's primitives can express |
| **You give up** | Nothing about the runtime; you operate it | Runtime features the target cloud has no home for |
| **Status** | Released | In development |

Orbit is the answer when you want the runtime and want it on GCP. Prisma is the answer when you
want the cloud's managed service to hold the workload, and you accept that its surface is smaller
than the runtime's — which is exactly why the coverage matrix exists.

## How it is put together

```
astromesh_prisma/
  spec/         the Astromesh manifest as pydantic models (Agent, RAGPipeline)
  mapping/      HomologMappingRegistry: spec field → native resource, plus the
                ManifestRouter that dispatches by kind, and the coverage generator
  providers/    CloudProvider protocol; gcp/ (GcpGateway) and fake/ (in-memory)
  reconcile/    the loop: desired vs observed, per (kind, name)
  state/        what has been observed, keyed by (kind, name)
  api/          the FastAPI surface over all of the above
```

Identity is `(kind, name)`, not `name`. A single-key store silently lost data when an Agent and a
RAGPipeline shared a name — which is why every route carries the kind.

### Native resources

`vertex.agent_engine` (carrying the ADK config, Memory Bank and the bindings) ·
`vertex.rag_corpus` · `modelarmor.template`

Tools are not resources. In GCP, what an agent can call lives inside its config. Resources that do
not exist were removed rather than kept as aspirational rows: `vertex.endpoint`, `vertex.reasoning`,
and a free-standing `vertex.memory_bank` that was never bound to an engine.

## The API

| Method | Route | What it does |
|---|---|---|
| `POST` | `/v1/specs` | Submit a manifest (`kind: Agent` or `kind: RAGPipeline`) |
| `GET` | `/v1/specs` | List submitted manifests |
| `GET` | `/v1/specs/{kind}/{name}` | Fetch one, with its observed state |
| `POST` | `/v1/specs/{kind}/{name}/reconcile` | Drive the cloud toward the spec |
| `POST` | `/v1/translate` | What a manifest becomes — resources and structured gaps — without storing it |

## What is not true yet

Being specific about this is the point of the project, so it belongs on its own page rather than in
a footnote:

- **Nothing is provisioned for real.** Every test and every run goes through the in-memory gateway.
  The real GCP gateway is designed and currently blocked on cloud authentication.
- **Bindings are not resolved yet.** Resolving `prisma://` references, building the engine's
  source archive and waiting on long-running operations are the gateway's job, and the gateway
  does not exist yet.
- **Marketplace distribution is not built.** One-click through a cloud marketplace is the
  distribution plan, not a current capability.
