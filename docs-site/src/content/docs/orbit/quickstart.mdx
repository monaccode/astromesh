title: Quick Start
description: Provision an Astromesh runtime on Google Cloud with Orbit — install, configure, plan, apply, verify and clean up.
---

import { Aside, Steps } from '@astrojs/starlight/components';

**You need:**

- Python 3.12+
- [OpenTofu](https://opentofu.org/docs/intro/install/) or Terraform. Orbit uses `$TOFU_PATH`,
  then `tofu`, then `terraform` from your `PATH`.
- A GCP project with billing enabled.
- Credentials: `gcloud auth login`, **or** `GOOGLE_APPLICATION_CREDENTIALS` pointing at a
  service-account key. With a key, Orbit also sets up the private services access Cloud SQL
  needs; with `gcloud` you set it up once yourself (see
  [GCP Provider](/astromesh/orbit/gcp-provider/#private-services-access)).

<Steps>

1. ## Install

   ```bash
   pip install astromesh-cli "astromesh-orbit[gcp]"
   astromeshctl orbit --help
   ```

   The `gcp` extra brings the Google client libraries used for validation, the state bucket
   and VPC peering.

2. ## Enable the APIs

   ```bash
   gcloud services enable run.googleapis.com sqladmin.googleapis.com redis.googleapis.com \
     secretmanager.googleapis.com vpcaccess.googleapis.com storage.googleapis.com \
     artifactregistry.googleapis.com monitoring.googleapis.com cloudtrace.googleapis.com \
     logging.googleapis.com --project my-project-123
   ```

   Orbit checks these ten but never enables them for you.

3. ## Write orbit.yaml

   ```bash
   astromeshctl orbit init
   ```

   The wizard asks for the project, the region, a deployment name, the environment
   (`develop`, `staging` or `production`) and a preset: `starter` (about $15/month) or `pro`
   (about $80/month, with HA database and cache). It writes `orbit.yaml` and adds `.orbit/` to
   `.gitignore`. `--preset starter` skips that question.

4. ## Plan

   ```bash
   astromeshctl orbit plan
   ```

   Orbit validates credentials, project and APIs, creates the state bucket if needed, renders
   `.orbit/generated/` and runs `plan`:

   ```
     Orbit Deployment Plan

     Validating... OK
     OK State bucket created: gs://my-project-123-astromesh-orbit-state

     Resources to create: …
   ```

   A failed check prints the command that fixes it and exits with code 1.

   <Aside type="note">
   The three counts come from scanning the plan's text and include attribute lines, so they
   run high. For the exact plan, run `tofu plan` in `.orbit/generated/`.
   </Aside>

5. ## Apply

   ```bash
   astromeshctl orbit apply
   ```

   It asks before creating billable resources (`--auto-approve` skips the question, for CI),
   then validates again and applies. The first apply takes several minutes; Cloud SQL and
   Memorystore are the slow ones. At the end it prints the runtime URL and writes
   `.orbit/orbit.env`.

6. ## Verify

   ```bash
   astromeshctl orbit status
   curl "$(grep RUNTIME_URL .orbit/orbit.env | cut -d= -f2)/v1/health"
   ```

   `status` lists `astromesh-runtime` with its URL. `orbit logs --since 10m` shows what the
   container printed.

   To use the runtime from [Cortex](/astromesh/cortex/runtimes/#google-cloud-run), add its URL
   as a remote runtime connection.

7. ## Clean up

   ```bash
   astromeshctl orbit destroy
   ```

   It asks first, then destroys everything Orbit created. The RAG bucket is created with
   `force_destroy = false`, so empty it before destroying or the destroy stops there. The state
   bucket is kept: delete it by hand once you are sure, with
   `gsutil rm -r gs://my-project-123-astromesh-orbit-state`.

</Steps>
