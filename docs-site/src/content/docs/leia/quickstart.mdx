## Requirements

- **Claude Code.**
- **Ollama** (optional). The architect runs `ollama list` and prefers a local model.
- For the operational commands: `curl`, and `kubectl` plus `kind` for a local cluster. See
  [Compatibility](/astromesh/leia/introduction/#compatibility) first.

## Load the plugin

Leia has no marketplace entry. Load it from a clone:

```bash
git clone https://github.com/monaccode/astromesh-leia.git
claude --plugin-dir ./astromesh-leia
```

`--plugin-dir` loads it for that session. The latest packaged release, `v0.4.0`, is a `.zip` and
a `.tar.gz` on the [releases page](https://github.com/monaccode/astromesh-leia/releases);
`v0.5.0` exists only on `main`.

Run `/leia` with no arguments to see the welcome menu. Claude Code lists the other commands
under the plugin's namespace, for example `/astromesh-leia:create`.

## Design an agent

<Steps>

1. **Describe it.**

   ```
   /leia necesito un bot de WhatsApp para mi pizzería que tome reservas
   ```

   The interpreter extracts the business, the channel (WhatsApp unless you say web), the
   vertical (`restaurant-booking` here) and any capabilities you named. If the intent is
   ambiguous it asks one question.

2. **Read the preview.** The architect writes a full manifest and explains its choices: the
   name (`pizzeria-…`, RFC 1123), the model and why, the pattern and why, and the assumptions
   you should check. It writes the file to `agents/<name>.yaml`.

3. **Answer** `yes`, `no` or `edit`. With `edit`, say what to change and it redesigns.

</Steps>

Prefer questions to a sentence? `/leia create` with no arguments runs a wizard: template,
channel, business name, description, and two or three questions specific to the template.

## Get it onto Nexus

Against a **Nexus 0.3.x** cluster, answering `yes` deploys the agent and polls until it is
`Ready`. Then:

```
/leia status
/leia test pizzeria-reservas
/leia logs pizzeria-reservas --follow
```

Against the **current Nexus**, publish the file Leia wrote with Cortex or the API:

```bash
curl -X POST "$NEXUS_URL/api/v1/agents" \
  -H "X-API-Key: $NEXUS_API_KEY" -H "Content-Type: application/yaml" \
  --data-binary @agents/pizzeria-reservas.yaml
```

<Aside type="note">
The templates use Ollama `llama3.1:8b`. On a managed hub, change the model to one the hub
serves before publishing.
</Aside>

## Connection contexts

Leia keeps connections in `~/.astromesh-leia/config.yaml`:

```yaml
current-context: local
contexts:
  local:
    nexus-url: http://localhost:8080
    api-key: nxk_...
    cluster-type: kind        # kind | remote
    cluster-name: nexus-local
    nexus-repo: ~/astromesh-nexus   # only for kind
defaults:
  channel: whatsapp
  model-provider: auto
  tenant: default
```

`/leia config add <name>` adds a context interactively and `/leia config use <name>` switches.
The API key is stored in that file in plain text.
