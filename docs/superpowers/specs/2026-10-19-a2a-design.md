# A2A en el ecosistema Astromesh — Diseño

**Fecha:** 2026-10-19 · **Estado:** aprobado por secciones en conversación (Juan Carlos), pendiente de revisión escrita.

## 1. Intención

Que cualquier agente —de Astromesh o de cualquier framework— pueda **delegar en otro agente y ser delegado** usando el estándar abierto **A2A (Agent2Agent) 1.0**, sin depender de CLARUS, y que esa capacidad se publique al mundo como componente Astromesh: la librería **`astromesh-a2a`**.

**Éxito:**
- En ≤5 líneas, un agente de LangChain/LangGraph, CrewAI, Google ADK, OpenAI Agents, PydanticAI, LlamaIndex, smolagents, Microsoft Agent Framework o MCP llama a un agente A2A remoto como herramienta.
- En ≤10 líneas, un agente (función async o LangChain) se expone como agente A2A con Agent Card.
- Con la política por defecto, la librería detiene el 100% de las trampas del eval de seguridad (SSRF, card falsa, inyección en artefactos, respuesta gigante, autoaprobación).
- El core de Astromesh, el ADK y Nexus hablan A2A: el core y el ADK a través de la librería; Nexus en Go, probado contra ella.

**Fuera de alcance de la v0.1:** gRPC binding, notificaciones push del lado cliente, adaptadores de servidor más allá de LangChain y función async, mercado/registro de agentes, firma de cards propias (sí se verifica la firma de cards ajenas si la política lo exige).

## 2. Contexto (medido)

- **Protocolo:** A2A 1.0 (Linux Foundation, AAIF desde ago-2026; 1.0.1 agrega extensiones). Card en `/.well-known/agent-card.json`; métodos JSON-RPC `SendMessage`, `SendStreamingMessage`, `GetTask`, `ListTasks`, `CancelTask`, `SubscribeToTask`, `*TaskPushNotificationConfig`, `GetExtendedAgentCard`; `TaskState` `TASK_STATE_{SUBMITTED,WORKING,COMPLETED,FAILED,CANCELED,INPUT_REQUIRED,REJECTED,AUTH_REQUIRED}`; SSE con `StreamResponse {task|message|statusUpdate|artifactUpdate}`; header `A2A-Version: 1.0`; errores -32001…-32099; campo `tenant`.
- **SDKs oficiales:** `a2a-sdk` (Python) 1.2.3, `github.com/a2aproject/a2a-go/v2` v2.6.0.
- **Huecos que el protocolo deja abiertos** (A2ABreak, análisis de gobernanza de MCP/A2A/ACP): suplantación de cards, inyección vía mensajes y artefactos, secuestro de tareas, SSRF en push, autorización delegada, observabilidad entre agentes.
- **Astromesh hoy:** no hay nada de A2A. Agente-a-agente es en proceso (`type: agent`, `core/tools.py:224-315`) o por el protocolo propio del ADK (`_remote.py`: `POST /v1/agents/{name}/run`, WS). Las corridas REST/WS/ADK remoto cuentan como **turnos humanos** (`desde_humano=True`, `engine.py:1392-1422`): un agente remoto puede autoconfirmar una acción con compuerta. No existe `skills` en el manifiesto. El costo de los sub-agentes no se suma al padre y `parent_trace_id` llega siempre vacío (`engine.py:2124-2141`). Nexus no tiene SSE, JSON-RPC ni rutas públicas con límite; `ParentInvocationID` nunca se escribe.
- **Librerías hermanas** (`astromesh-rag`, `astromesh-context`, `astromesh-okf`): repo propio, Apache-2.0, deps mínimas, un extra por framework, README + README.es, `docs/`, `examples/`, `assets/` (logo-mark.svg, logo.png, icon.png), CI + PyPI con trusted publishing.

## 3. La librería `astromesh-a2a`

### 3.1 Enfoque

Capa **sobre el SDK oficial** `a2a-sdk` (dependencia obligatoria). El protocolo lo pone el SDK; el valor propio es lo operativo y de seguridad: salida de red segura, política de remotos, origen del turno, presupuestos, trace, adaptadores de framework y un eval de trampas. Descartadas: implementación propia (riesgo de conformidad) y solo-adaptadores (sin API única para core/ADK).

### 3.2 Módulos

| Módulo | Responsabilidad | Depende de |
|---|---|---|
| `client` | `RemoteAgent`: card → envío (bloqueante o stream) → seguimiento de la Task → `responder()` en `input-required` → `cancelar()`. Devuelve `Resultado`. | a2a-sdk, `net`, `policy`, `trace` |
| `server` | `serve(agente, card)` / `crear_app(...)`: envuelve una función async o un agente de framework en un `AgentExecutor` del SDK; genera la card desde `CardSpec` (con skills). | a2a-sdk, `policy`, `trace`, extra `server` |
| `net` | Salida segura: resolución + bloqueo de rangos internos, IP pineada con SNI/Host correctos, sin redirecciones, tope de cuerpo (portado de `astromesh/tools/builtin/_red.py`). | httpx |
| `policy` | `Politica`: `permitidos` (hosts/URLs de card), `exigir_firma`, `presupuesto` (llamadas y segundos por remoto), `partes_aceptadas` (text/data por defecto; file opt-in), `tope_bytes`, `timeout`. Valores seguros por defecto. | — |
| `trace` | Entradas por etapa (`card`, `envio`, `estado`, `artefacto`, `rechazo`) con ms, bytes y motivo; `traceparent` W3C; costo/latencia si el remoto los informa. Export dict; OpenTelemetry con extra `otel`. | — |
| `adapters/` | Cliente → herramienta para langchain, crewai, adk, openai-agents, pydantic-ai, llamaindex, smolagents, agent-framework, mcp. Servidor → langchain y función async. | extras |
| `eval` | Agentes trampa locales y métrica de detención. | `server` |

### 3.3 Semántica del cliente

1. **Card:** se descarga por `net`, se valida contra la `Politica` (host permitido, firma si se exige, versión 1.x). Caché con TTL. Si falla → `RechazoPolitica`, sin enviar nada.
2. **Envío:** `role: ROLE_USER`, `contextId` estable por conversación, metadatos `origen` (`agente` por defecto; `humano` sólo si el llamador lo declara), `traceparent`, header `A2A-Version: 1.0`. Auth desde variables de entorno (API key, bearer, OAuth client-credentials); nunca en el trace ni en errores.
3. **Respuesta:** `Message` = inmediata; `Task` = se sigue por stream o polling según `capabilities`, con tope de tiempo total y de eventos.
4. **Normalización:** partes texto → `respuesta`; partes data → `datos` si pasan tamaño y esquema opcional; file rechazadas salvo opt-in. **Todo lo que viene del remoto es no confiable**: los adaptadores lo entregan al modelo envuelto como dato, nunca como instrucción.
5. **Estados:** `COMPLETED` → ok; `INPUT_REQUIRED`/`AUTH_REQUIRED` → `Resultado` pendiente con la pregunta y el `taskId` (`responder(task_id, texto)`). La librería **nunca contesta sola una confirmación**: la devuelve al modelo/humano del lado que llama. `FAILED`/`REJECTED`/`CANCELED` → `TareaFallida`.

### 3.4 Semántica del servidor

1. Card en `/.well-known/agent-card.json`, JSON-RPC en `/a2a`, negociación de versión; montable en Starlette/FastAPI o standalone.
2. Cada mensaje entrante invoca al agente con `Origen.AGENTE` y el texto marcado no confiable. Si el agente pide confirmación → `INPUT_REQUIRED`. **Una respuesta del remoto nunca cuenta como confirmación humana**: el hook `confirmar` lo resuelve sólo un humano del lado servidor.
3. Auth entrante por callable (helper de API key). Sin auth configurada el servidor no arranca salvo `inseguro=True`.

### 3.5 Errores

Base `ErrorA2A`: `RechazoPolitica`, `DestinoBloqueado`, `TareaFallida`, `Tiempo`, `VersionNoSoportada`, `ConfirmacionRequerida`. Ningún mensaje lleva credenciales; los adaptadores los traducen al error del framework sin stack.

### 3.6 Pruebas

Unitarias con `respx`; **interoperabilidad** cliente-propio↔servidor-de-referencia del SDK y servidor-propio↔cliente-oficial; un test por adaptador con remoto falso; el eval de trampas en CI con meta 100% con la política por defecto (número publicado en el README).

### 3.7 Empaquetado e identidad

- Python ≥3.10, Apache-2.0. Deps base: `a2a-sdk>=1.2,<2`, `httpx`, `pyyaml`. Extras: `langchain`, `crewai`, `adk`, `openai-agents`, `pydantic-ai`, `llamaindex`, `smolagents`, `agent-framework`, `mcp`, `server`, `otel`, `all`.
- `uv.lock` versionado; CI ruff + pytest; release por tag a TestPyPI → smoke → PyPI (trusted publishing).
- Repo **`monaccode/astromesh-a2a`**: README (EN) + README.es, CHANGELOG, CONTRIBUTING, LICENSE, `docs/` (`client.md`, `server.md`, `politica.md`, `frameworks.md`, `eval.md`, `ecosistema.md`), `examples/`, `assets/` (`logo-mark.svg`, `logo.png`, `icon.png`) con la identidad Astromesh; motivo: dos nodos que se pasan una tarea por un canal custodiado.
- Ficha en el docs-site de Astromesh (sección ecosistema) y página propia, como `astromesh-rag`.

## 4. Integración en el ecosistema (fases)

| Fase | Qué | Repos |
|---|---|---|
| 0 | **Origen del turno**: campo `origen: humano\|agente` en `POST /v1/agents/{name}/run` y WS (default `humano`, compatible); el ADK remoto y todo llamador agente mandan `agente` → `desde_humano=False`. **Trace padre-hijo**: `trace_id` en el contexto de `tool_fn`. **Costo de sub-agentes** sumado al uso del padre (Nexus factura sobre ese uso). **`spec.skills`** en el manifiesto (id, name, description, tags, examples, inputModes, outputModes), en el JSON schema, docs y `GET /v1/agents/{name}`. | core |
| L | **Librería `astromesh-a2a` v0.1** (secciones 3.x). | astromesh-a2a (nuevo) |
| 1 | **Nexus servidor A2A** con `a2a-go/v2`: card por agente publicado (opt-in `spec.a2a.publicar: true`, default apagado), JSON-RPC `SendMessage`/`SendStreamingMessage` (SSE)/`GetTask`/`CancelTask`, Task = invocación (estado mapeado), `contextId` ↔ session, auth = API key/JWT del tenant declarados en `securitySchemes`, corrida con `origen: agente`. Conformidad probada con el cliente de `astromesh-a2a`. | nexus |
| 2 | **Cliente en core y ADK**: tool `type: a2a` (`card_url`, `auth_env`, `politica`, `timeout`) sobre `astromesh-a2a` (extra `a2a` del core), con `INPUT_REQUIRED` devuelto al modelo como observación y `taskId` recordado por sesión; Forge y schema; `remote_a2a()` en el ADK. | core, ADK, Forge |
| 3 | **Tareas asíncronas y push en Nexus**: `returnImmediately` → Task `SUBMITTED` corriendo en background, `SubscribeToTask`, cancelación entre pods vía store, push con egress seguro y firma. | nexus |
| 4 | **PAP en CLARUS** (agente del negocio para agentes personales, A2A público con OAuth/scopes). **Compuerta G3**: espera la spec PAP v0.1. | clarus, nexus |

## 5. Decisiones

1. Capa sobre `a2a-sdk` / `a2a-go`, no implementación propia.
2. Origen por defecto `agente` en todo lo que habla A2A; la API REST conserva `humano` por compatibilidad y gana el campo explícito.
3. Una respuesta de otro agente nunca cuenta como confirmación humana, en ningún lado.
4. Exponer un agente por A2A es opt-in por agente (Nexus) o explícito (`serve`), con auth obligatoria.
5. Lo que llega de otro agente es entrada no confiable, en ambos sentidos.
6. Nexus no usa la librería (Go): se prueba contra ella.

## 6. Riesgos

- Cambios de la spec 1.x (extensiones) → fijar `a2a-sdk<2`, `a2a-go/v2`, y tests de interop en CI.
- `a2a-go` v2 aún joven → spike al inicio de la fase 1 que fija su API antes de construir.
- Facturación de sub-agentes (fase 0) cambia montos en Nexus → anotarlo en el CHANGELOG del core y verificar con un test de Nexus antes del release.
- Prompt injection residual vía texto del remoto → mitigado por envoltura como dato + guardrails del agente que recibe; no eliminable por protocolo.
