# A2A Fase 0 — Origen del turno, trace y costo de sub-agentes, skills · Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que el core distinga turnos humanos de turnos de agente en todas sus entradas, que los sub-agentes queden en el trace y en la factura del padre, y que el manifiesto declare `skills` para generar Agent Cards.

**Architecture:** Cambios acotados en `astromesh/api` (campo `origen`), `astromesh/runtime/engine.py` (contexto de `tool_fn`, uso agregado) y el manifiesto (`spec.skills` leído por el runtime, expuesto en la API y validado por el JSON schema). El ADK manda `origen: agente` en `remote()`.

**Tech Stack:** Python 3.12, FastAPI, pytest (asyncio auto), respx, ruff.

**Spec:** `docs/superpowers/specs/2026-10-19-a2a-design.md` §4 fase 0.

**Rama:** `feat/a2a` (worktree `D:/monaccode/_wt/astromesh-a2a`, desde `origin/develop` 0.72.0).

## Global Constraints

- `origen` acepta exactamente `"humano"` y `"agente"`; default `"humano"` (compatibilidad); `desde_humano = (origen == "humano")`.
- Una respuesta de otro agente nunca cuenta como confirmación humana (spec §5.3).
- `spec.skills[]` campos: `id` (requerido), `name` (requerido), `description` (requerido), `tags`, `examples`, `inputModes`, `outputModes` (camelCase, como A2A).
- Gate antes de cada commit: `uv run ruff check astromesh/ tests/ && uv run ruff format --check astromesh/ tests/ && uv run pytest -q <tests tocados>`; suite completa una vez al final de cada tarea.
- CHANGELOG `[Unreleased]` en todo `feat`/`fix` (regla de CLAUDE.md); cambios del ADK también en `astromesh-adk/CHANGELOG.md`.
- No bumpear versiones en este plan (el release 0.73.0 cierra la fase 2).

## Review Focus

1. **`origen` con valor inválido** (`"bot"`, mayúsculas): debe dar 422, no caer en humano. → `test_run_origen_invalido_422` (T1).
2. **Sub-agente que falla a mitad**: el uso ya consumido por el hijo igual se suma al padre. → `test_costo_hijo_fallido_se_suma` (T3).
3. **Sub-agente anidado (nieto)**: el costo sube dos niveles y el trace mantiene el mismo `trace_id`. → `test_costo_nieto_llega_a_la_raiz` (T3).
4. **Manifiesto con `skills` mal formado** (sin `id`): el agente carga con warning y la skill inválida se omite; no rompe el runtime. → `test_skills_invalidas_se_omiten` (T4).
5. **WS con `origen: agente`** y luego un mensaje "si": no habilita ninguna confirmación. → `test_ws_origen_agente_no_confirma` (T1).

### Task 3: Trace y costo de sub-agentes en el padre

**Files:**
- Modify: `astromesh/runtime/engine.py` (contexto de `tool_fn` ~L2124-2141; acumulación de uso)

- Test: `tests/test_subagente_trace_costo.py` (crear)

**Interfaces:**
- Produces: el resultado de un run (`result["usage"]` / `usage.by_model`) incluye el uso de todos los sub-agentes (`type: agent`) ejecutados, a cualquier profundidad; los sub-agentes corren con `parent_trace_id == trace_id del padre`.

- [ ] **Step 1: Tests que fallan** (proveedores falsos con usage conocido):

  - `test_costo_hijo_sumado_al_padre`: padre 100/50 tokens, hijo 200/80 → `usage` del run REST suma 300/130 y `by_model` lista ambos modelos con sus costos.
  - `test_costo_nieto_llega_a_la_raiz`: padre→hijo→nieto, el uso de los tres aparece en la raíz.
  - `test_costo_hijo_fallido_se_suma`: el hijo consume tokens y luego lanza; el padre falla, pero el uso parcial queda en el resultado de error que lee Nexus (o en el trace si el error no lleva usage — documentar cuál y testear ese).

- [ ] **Step 2:** → FAIL.
- [ ] **Step 3:** Agregar `trace_id` al contexto de `tool_fn` y acumular el uso del hijo en el contador de uso del padre (un único acumulador por run raíz, pasado por contexto, no global).
- [ ] **Step 4:** → PASS; suite completa.
